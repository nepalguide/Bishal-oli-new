1. Executive Design & SEO Brief
BishalOli.com should function as a personal expert platform, a Nepal-focused commercial SEO site, a research/education property, and an evidence repository. The site should not look or behave like a broad digital-marketing agency.
Core ruleEvery page should strengthen at least one of five things: (1) Bishal Oli as an entity, (2) Semantic SEO / Topical Authority / AI Search expertise, (3) Nepal commercial relevance, (4) first-hand evidence, or (5) acquisition/education/conversion.
Strategic objectives
Own high-intent Nepal SEO queries through dedicated commercial pages instead of relying on a single “SEO Expert in Nepal” URL.
Build a defensible expertise moat around Semantic SEO, Topical Authority and AI Search.
Turn real client work, experiments and measurable outcomes into first-class website assets.
Build local prominence through legitimate business information, genuine reviews, local mentions, partnerships and useful Nepal-specific research.
Convert educational traffic into training, consulting and qualified SEO leads without making every page sales-heavy.

3.4 Layout language
Use generous whitespace and a strong 12-column desktop grid.
Preferred content width: 1120–1240 px; long-form text column: roughly 680–780 px.
Use 12–16 px corner radii for cards and 10–12 px for controls; avoid excessive pill-shaped UI.
Use 1 px borders and very subtle shadows. Avoid glossy “agency template” effects.
Use dark sections strategically: hero, proof/results, selected CTA bands, footer.
Use light editorial sections for long-form expertise and training content.
Use blue gradients only as subtle light/glow treatments; never as the base of every component.
3.5 Photography
Primary portrait: high-quality professional headshot with natural expression and clean background; one consistent hero portrait should become an entity-recognition asset.
Use Nepal imagery as contextual evidence of market identity, not as decorative tourism stock.
Prefer editorial, authentic imagery: Kathmandu work settings, workshops, speaking, client/project context, trekking/travel projects when relevant.
Avoid generic laptop/coffee stock images unless they add real context.
Keep image treatment consistent: deep navy overlay only when needed, natural highlights, restrained saturation.
3.6 Iconography & graphics
Use a single line-icon family with consistent stroke weight.
Prefer geometric diagrams for semantic relationships, topical maps, entity graphs and internal-linking structures.
Use data visuals to demonstrate results rather than decorative infographics.
Do not overload pages with icons. One strong diagram is more valuable than six decorative icons.

10. Technical SEO & Development Specification
Architecture
Use clean, stable URLs with logical directories.
Keep important pages within a shallow, crawlable click path.
Generate XML sitemap(s) automatically and keep them limited to canonical indexable URLs.
Use robots.txt only for crawl directives that are actually needed.
Avoid accidental noindex, canonical conflicts and orphan pages.
Use breadcrumbs for deep content where they improve orientation.
Rendering & performance
Mobile-first responsive implementation.
Optimize LCP image and above-the-fold media; use modern formats such as AVIF/WebP when appropriate.
Lazy-load non-critical below-the-fold images.
Minimize JavaScript and third-party scripts.
Reserve image dimensions to prevent layout shift.
Use a CDN and long-lived caching for static assets.
Set internal performance budgets for JavaScript, CSS, images and fonts; validate with real-user and lab data.
Accessibility
Target WCAG 2.2 AA-level accessibility as the implementation standard.
Keyboard navigability for menus, accordions, forms and dialogs.
Visible focus states.
Sufficient text/background contrast.
Meaningful alt text for informational images; decorative images should be treated as decorative.
Do not convey meaning through color alone.
Buttons and links need descriptive labels.

19. Developer Handoff Rules
Build the global design system before page-specific styling.
Implement the header, footer, buttons, typography, card and spacing tokens as reusable components.
Build the homepage and one canonical commercial landing-page template first.
Build one long-form knowledge-page template and one case-study template.
Build one geographic landing-page template only after the national template is stable.
Use data-driven content blocks for repeated card patterns so future sitemap expansion does not require new component code.
Keep SEO metadata and schema generated from page-level configuration rather than hard-coded into each component.
Keep canonical URL, breadcrumbs and internal-link structures derived from the approved sitemap.
Create a design-token layer so the brand can evolve without editing individual pages.
Do not allow ad-hoc colors, fonts, shadows, border radii or button styles to accumulate.

21. Final Strategic Architecture
Bishal Oli should be represented as a Nepal-first SEO expert/consultant whose authority is centered on Semantic SEO, Topical Authority and AI Search.
